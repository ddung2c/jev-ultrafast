ARGO × jev — desktopweb 실행기 치환

VIA 파이프라인 안에서 정확히 무엇이 그대로이고, 무엇이 jev로 바뀌었는지.

맞습니다 — ARGO를 고친 게 아니라, ARGO의 desktopweb lane 하나를 jev로 우회시킨 겁니다.

음성/텍스트 입력, Context Engine, Evaluator(요청을 어느 lane으로 보낼지 결정하는 LLM), Router, capability card 8개 — 이 전부가 그대로입니다. Evaluator는 지금까지와 똑같이 "이건 desktopweb lane 일이다"라고 판단합니다.

다른 점은 그 판단 이후, 실제로 브라우저를 조작하는 실행기뿐입니다. 원래는 ARGO 자체의 tinicore ReAct 루프(스텝마다 LLM이 DSL을 새로 생성)가 맡았는데, 이번 벤치에서는 그 자리에 jev(TypeSafe가 요소 표에서 선택)를 대신 꽂았습니다. 실패하면 원래 ARGO 실행기로 되돌아가는 fallback도 설계에 포함되어 있습니다(아직 실제 argo-pc에는 미구현, 벤치 전용).

출처: docs/via-argo-bench-design.md, docs/via-vs-argo.md, ARGO PR #3446 (docs/plans/FASTWEB_JEV_FUSION.md). 측정: macOS, 같은 Chrome 프로필, 같은 LLM(deepseek-chat), A/B 교대 3회씩.
