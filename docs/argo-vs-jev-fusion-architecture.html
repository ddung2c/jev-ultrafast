argo-pc 기존 구조 vs jev fusion 구조

같은 발화가 두 구조에서 어디까지 같은 길을 가고, 어디서 갈라지는지.

jev가 실패하면 ARGO로 넘어가나요? — 설계상으로는 그렇습니다. jev-via가 실패로 끝나면(exit code ≠ 0, 즉 blocked 또는 error) VIA의 CliAgent가 이를 Failed로 받습니다. 그러면 같은 goal을 argo-pc에 원래 있던 desktopweb 서브에이전트(tinicore ReAct 루프)로 다시 보내는 구조입니다.

단, 이 폴백은 아직 구현되지 않았습니다. 이번 A/B 벤치에서는 jev가 3/3 성공해서 폴백이 필요한 상황도 없었지만, 실패했다면 그 턴은 그대로 실패로 끝났을 겁니다. 구현하려면 Failed를 받았을 때 기존 Orchestrator::dispatch_direct(correction 재디스패치 경로)로 desktopweb에 다시 보내면 됩니다.
