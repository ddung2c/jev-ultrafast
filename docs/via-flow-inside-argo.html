VIA × jev — argo-pc 배포 기준으로 다시 그림

VOICE_INTERACTION_API_FLOW.html의 ①~④(Voice Edge · Context Engine · Evaluator · Router) 자체가 이미 argo-pc 프로세스다. "Router → ARGO" 화살표는 다른 배포 시나리오이고, argo-pc 안에서 Router는 곧바로 desktopweb을 포함한 8개 lane으로 나간다.

이전 버전 정정

이전 그림은 "⑤ ARGO 박스 안에 두 번째 VIA 인스턴스가 내장되어 있다"고 그렸는데, 이건 잘못 그린 겁니다. via-core는 딱 한 벌만 돌아갑니다. via_ask.rs::build_orchestrator()가 만드는 단 하나의 Router가 바로 8개 lane(desktopweb 포함)을 등록합니다 — 그 사이에 "ARGO"라는 이름의 별도 agent를 한 번 더 거치지 않습니다.

VOICE_INTERACTION_API_FLOW.html의 "Router → claude-code / ARGO / gemini" 그림은 여러 기기·여러 에이전트로 위임하는 다른 배포(예: 폰의 VIA가 PC의 ARGO CLI를 A2A로 부르는 경우)를 그린 것입니다. argo-pc 자신을 켰을 때는 이 경로를 타지 않습니다.

argo-pc 배포에서는 ①Voice Edge부터 ④Router까지가 전부 argo-pc 프로세스 안에서 돌아가고, Router는 "ARGO"라는 이름을 거치지 않고 바로 answer·files·windows·desktop·desktopweb·tools·cancel·correction 8개 lane 중 하나로 dispatch합니다. 이번에 바뀐 건 이 중 desktopweb lane이 호출하는 대상뿐입니다 — 아래 그림 참고.
